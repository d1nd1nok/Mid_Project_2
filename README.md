# Diplom_2

Вторая часть дипломного проекта курса «Инженер по тестированию» (Яндекс Практикум): API-автотесты для сервиса [Stellar Burgers](https://qa-stellarburgers.education-services.ru/) на `requests` и pytest с Allure-отчётом.

## Стек

- Python 3
- pytest
- requests
- Faker — генерация тестовых данных
- Allure (`allure-pytest`)

## Структура проекта

```
Diplom_2/
├── conftest.py               # фикстуры: registered_user, authorized_user, cleanup_users
├── src/
│   ├── urls.py               # базовый URL и эндпоинты API
│   ├── user_heplers.py       # User — регистрация, логин, изменение данных, удаление; тексты ошибок
│   └── order_helpers.py      # Order — ингредиенты, создание заказа, получение заказов
├── test/
│   ├── test_register_user.py     # TestRegisterUser — создание пользователя
│   ├── test_login_user.py        # TestLoginUser — логин пользователя
│   ├── test_change_user_data.py  # TestChangeUserData — изменение данных пользователя
│   ├── test_create_order.py      # TestCreateOrder — создание заказа
│   └── test_get_user_orders.py   # TestGetUserOrders — заказы конкретного пользователя
└── allure-results/           # результаты прогона для Allure-отчёта
```

## Покрытые ручки

| Ручка | Метод | Тесты |
|-------|-------|-------|
| `/api/auth/register` | `POST` | Уникальный пользователь, повторная регистрация, отсутствие `name` / `email` / `password` (параметризация) |
| `/api/auth/login` | `POST` | Логин существующим пользователем, неверный `email` / `password` (параметризация) |
| `/api/auth/user` | `PATCH` | Изменение `name` / `email` / `password` с авторизацией (параметризация), изменение без авторизации, смена email на уже занятый |
| `/api/orders` | `POST` | С авторизацией и без, с ингредиентами, без ингредиентов, с неверным хешем ингредиента |
| `/api/orders` | `GET` | Заказы авторизованного и неавторизованного пользователя |

Пользователи, созданные в тестах, удаляются после проверки через `DELETE /api/auth/user` — это делают фикстуры из [conftest.py](conftest.py).

## Запуск

1. Создайте виртуальное окружение и установите зависимости:

   ```bash
   python3 -m venv venv
   source venv/bin/activate
   pip install pytest requests faker allure-pytest
   ```

2. Запустите тесты с сохранением результатов для Allure:

   ```bash
   pytest test --alluredir=allure-results
   ```

3. Откройте отчёт (нужен установленный [Allure CLI](https://allurereport.org/docs/install/)):

   ```bash
   allure serve allure-results
   ```

## Задание

Протестируй ручки API для Stellar Burgers. В документации API описаны все эндпоинты сервиса, но тестировать нужно только те, что указаны в задании — остальное для контекста.

### Создание пользователя

- создать уникального пользователя;
- создать пользователя, который уже зарегистрирован;
- создать пользователя и не заполнить одно из обязательных полей.

### Логин пользователя

- логин под существующим пользователем;
- логин с неверным логином и паролем.

### Изменение данных пользователя

- с авторизацией;
- без авторизации.

Для обеих ситуаций нужно проверить, что любое поле можно изменить. Для неавторизованного пользователя — ещё и то, что система вернёт ошибку.

### Создание заказа

- с авторизацией;
- без авторизации;
- с ингредиентами;
- без ингредиентов;
- с неверным хешем ингредиентов.

### Получение заказов конкретного пользователя

- авторизованный пользователь;
- неавторизованный пользователь.

### Что нужно сделать

1. Создай отдельный репозиторий для тестов API.
2. Подключи библиотеки: pytest, requests и allure-pytest.
3. Напиши тесты.
4. Сделай отчёт в Allure.
